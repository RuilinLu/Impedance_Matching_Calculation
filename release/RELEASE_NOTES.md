## 本次更新

### 1. 长对话滚动与清空

- 修复右侧浮动助手消息被 flex 压缩、长对话无法上下滚动的问题；关闭再打开才能滚动的情况不再出现。
- 主聊天移除逐 token 启动的 smooth-scroll 队列，改为 `requestAnimationFrame` 帧节流和即时滚动；用户上翻阅读时不会被强制拉回底部。
- 主聊天与浮动助手都新增“新对话”按钮；清空只删除对话，不删除报告、教材索引、上传文件或个人设置。

### 2. 停止、编辑与重新发送

- 回答期间发送键变成转圈停止键，点击立即中断并保留已生成文本，显示“已停止生成”。
- 思考或回答期间按 Enter 不会重复发送；中断后发送键、`aria-busy`、统计区域正确复位。
- 每条用户消息悬停可“编辑 / 复制”；编辑保存后从该问题处截断后续对话并重新发送。
- 会话使用 generation 序号，清空或重发后旧的流式响应不会写回新对话。

### 3. 多厂商模型连接

- 设置 → 模型服务保存多个服务商 / Base URL / Key / 模型连接；主聊天和浮动助手共享模型选择器。
- 切换连接通过 `/api/connections/activate` 同步活动模型、状态栏与用量统计。
- 修复“切换第二个厂商但未重填 Key”时误用上一个活动厂商 Key 的问题；每个连接独立保存自己的 Key。
- 公共配置接口只返回 `has_key` 与掩码提示，不返回明文 Key。

### 4. 多模态输出

- 模型响应中的 `image` / `audio` / `video` / `file` 内容块转换为媒体事件。
- 回答中的图片、视频、音频、PDF/数据文件以媒体卡片显示，可预览、下载、复制图片、复制链接和打开。
- `get_smith_trajectory` 在服务端生成 Smith 圆图 SVG（`/api/media/…`），聊天中直接显示并可下载。
- 媒体路由只允许白名单文件名和数据目录内文件，目录穿越返回 404。

### 5. LaTeX 复制

- 每个公式保留 `data-latex` 原文；点击行内或独立公式即可复制 TeX 源码。
- 独立公式悬停显示“复制 LaTeX”按钮。
- 每条回答提供“复制回答（含 LaTeX 源码）”和“复制全部公式”，不再只能复制到 MathJax 生成的 SVG 文本。

### 6. 显示开关与网络引用

- 按钮更名为“展示思考链路 / 显示引用 / 显示工具调用”，设置、主聊天和浮动助手三处同步。
- 工具卡片默认隐藏，只显示一行“正在调用本地工具…”状态，回答更清爽。
- 引用卡片新增 `web` 类型，网络资料以可点击超链接显示；Markdown 裸链接自动转换为超链接。

### 7. 智谱 GLM 目录

- 补充 GLM-5.3、GLM-5.3-Flash、GLM-5.3-FlashX、GLM-5.2、GLM-5.1、GLM-4.7、GLM-4.6V 等 21 个文本/视觉模型。
- 模型选择器同时显示目录模型与已保存连接中发现的模型。

### 8. 安装与卸载

- 卸载器改为自定义表单，默认勾选“保留我的个人数据、设置、教材索引与文件库”；只有取消勾选才彻底删除。
- 安装器检测到已有 `config.json`、教材索引或 `TextBook` 时显示复用确认页；覆盖安装不会清空 Key 或索引。
- 保留模式下程序目录 `TextBook` 会先复制到用户数据目录。

### 9. MCP HTTP 会话与教材库并发

- 携带未知或已过期 `Mcp-Session-Id` 的请求现在返回 HTTP 404 与 JSON-RPC `-32000 Unknown or expired session`，不再静默创建新会话。
- 正常会话、stdio、批量工具调用与 HTTP 传输继续可用；该修复阻止异常客户端用随机 SID 无限创建会话。
- 教材库不再每个连接执行 `PRAGMA journal_mode=WAL`；WAL 只初始化一次，`busy_timeout=30000`，schema 初始化按数据库路径缓存。
- 强制重建索引时并发 123 个搜索/状态/AI 搜索请求：0 错误、无 `database is locked`。

## 兼容性

- 直接读取 4.3.x/4.4.x 的 `config.json`、教材 SQLite 索引、上传与报告目录。
- 旧 REST/MCP 参数保持兼容；`connection_id`、`show_tools`、媒体事件为新增可选能力。
- 4.5.x 作为后续版本的兼容基线。

## 已知限制

- 更新检查需要访问 `api.github.com`；离线/代理环境回退到缓存或手动检查。
- 教材翻译质量与速度取决于用户配置的模型；思考模型可能需要更高输出预算。
- OCR 仍为 CPU 推理，扫描版教材首次 OCR 需要时间。
- 第三方模型是否支持视觉/视频输出取决于该厂商 API；文本模型只会返回媒体链接或说明。
